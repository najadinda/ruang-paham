2. PROMPT DEBUGGING — STABILISASI AUTENTIKASI
============================================================

Log asli: Prompt #43

PROMPT ASLI:
------------------------------------------------------------
Lakukan investigasi menyeluruh, debugging, dan perbaikan terhadap sistem authentication pada project Ruang Paham yang sudah dikembangkan.
MASALAH UTAMA:
Ketika website baru dijalankan, dibuka kembali, atau siswa mencoba login, terkadang muncul error:
Failed to execute 'json' on 'Response': Unexpected end of JSON input
Masalah ini berulang dan mengganggu proses login siswa.
TUJUAN UTAMA:
Memastikan sistem authentication berjalan stabil, tidak mengalami error parsing JSON akibat implementasi yang salah, dan dapat digunakan secara konsisten tanpa harus memperbaiki kode atau konfigurasi setiap kali website dijalankan.
Jangan hanya menyembunyikan pesan error. Temukan dan perbaiki akar penyebabnya.
------------------------------------------------------------

MENGAPA PROMPT INI EFEKTIF
--------------------------
  * Menyebut pesan error persis dan kapan muncul (saat website baru dijalankan, dibuka kembali, atau login).
  * Menetapkan tujuan yang terukur: stabil tanpa perbaikan manual berulang.
  * Ada larangan eksplisit: "Jangan hanya menyembunyikan pesan error", sehingga AI dipaksa mencari akar masalah.

AKAR MASALAH YANG DITEMUKAN
---------------------------
1. 215 file bundle usang menumpuk di backend/public/assets/ karena emptyOutDir: false. Sebanyak 37 di antaranya masih memanggil res.json() mentah.
2. fetch() tanpa error trapping di services/api.js, jadi respons kosong atau backend belum siap langsung crash.
3. Token cacat ("undefined" / "null") tersimpan di localStorage pada AuthContext.jsx.
4. Tidak ada header no-cache pada SPA catch-all di routes/web.php.
5. Vite proxy tidak mengembalikan JSON 503 saat backend belum siap.

HASIL
-----
  * Fungsi request() terpusat yang selalu membaca res.text() lalu parsing kondisional.
  * Pesan error ramah anak per kode status (502/503/504, 419, 404, 422, 401, 500+).
  * Plugin cleanAssetsPlugin di Vite: aset usang berkurang dari 215 menjadi 13 file.
  * Header no-cache dan fallback JSON 404 untuk rute api/*.
  * 14 dari 14 skenario uji lulus, termasuk PHPUnit dan build frontend.

CATATAN PEMBELAJARAN
--------------------
Prompt debugging terbaik berisi gejala, kondisi pemicu, tujuan, dan larangan solusi tambal-sulam.

MENGAPA PROMPT INI EFEKTIF
--------------------------

  * Menyebut batasan lingkungan (tidak ada terminal) dan prioritas: tercepat, aman, minimal.

AKAR MASALAH
------------
1. Query API bukan penyebab. Tabel subjects di produksi memang berisi 0 record.
2. Seeder memakai SET FOREIGN_KEY_CHECKS (sintaks MySQL) yang gagal di SQLite Docker.
3. Dockerfile memakai || true pada db:seed, sehingga kegagalan seeder tersembunyi.
4. Tanpa SSH/console, seeder tidak bisa dijalankan manual.

SOLUSI MINIMAL & AMAN
---------------------
  * SubjectSeeder, LessonSeeder, QuizSeeder memakai updateOrCreate dan chunk insert (tanpa truncate() dan tanpa SET FOREIGN_KEY_CHECKS).
  * Auto-seed aman di AppServiceProvider::boot(): hanya jalan sekali bila subjects kosong, tanpa endpoint publik, dan tidak menyentuh users atau user_progress.
  * Dockerfile: || true dihapus agar kegagalan seed terlihat saat build.

HASIL VERIFIKASI
----------------
8 mata pelajaran, 67 materi, dan 670 kuis termuat; data akun dan progress siswa tetap utuh; GET /api/subjects?grade=3 dan grade=4 mengembalikan 8 mapel.

CATATAN PEMBELAJARAN
